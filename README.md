# מאגר הגמ"חים: Backend

שרת (Backend) למערכת "מאגר הגמ"חים": כל גמ"ח מתפרסם עם הפרטים והחפצים שלו, וכל אחד יכול למצוא גמ"ח או חפץ קרוב לביתו.

> **רוצה להעלות את השרת לאינטרנט?** פתחי את [`START-HERE.md`](START-HERE.md).
> **רוצה לכתוב את צד ה-React?** פתחי את [`docs/FRONTEND-API-GUIDE.md`](docs/FRONTEND-API-GUIDE.md).
> **האפיון המלא (טבלאות, הרשאות, Endpoints):** [`docs/SPEC.md`](docs/SPEC.md).

## מה בפנים

| רכיב | טכנולוגיה |
|---|---|
| שרת | Node.js 22 + Express + TypeScript (מצב strict) |
| מסד נתונים | PostgreSQL + Prisma ORM (עם מיגרציות) |
| ולידציה | Zod (הודעות שגיאה בעברית) |
| התחברות | JWT + סיסמאות מוצפנות (bcrypt) |
| תיעוד API | Swagger UI ב-`/api-docs` + קובץ `openapi.json` |
| בדיקות | Vitest + Supertest, מול PostgreSQL אמיתי |

## תפקידים

| תפקיד | מה אפשר |
|---|---|
| אורח (בלי התחברות) | לחפש ולצפות בגמ"חים ובחפצים |
| לקוח (`CUSTOMER`) | הכול כמו אורח, ובנוסף לבקש להפוך למנהל גמ"ח |
| מנהל גמ"ח (`GEMACH_MANAGER`) | לנהל את הגמ"חים שלו: פרטים, חפצים והשאלות |
| מנהל ראשי (`ADMIN`) | לאשר בקשות, לנהל תפקידי משתמשים, להוסיף ולמחוק גמ"חים, ולצפות בהשאלות |

## הרצה מקומית במחשב

דרוש: Node.js (גרסה 20 עד 24) ומסד PostgreSQL לפיתוח. אם אין לך PostgreSQL מקומי, אפשר להשתמש במסד חינמי בענן (ראי חלק ב' ב-`START-HERE.md`) ולהדביק את הכתובת שלו ב-`.env`.

```bash
npm install
cp .env.example .env        # ואז לערוך את .env (DATABASE_URL ו-JWT_SECRET)
npx prisma migrate deploy   # יוצר את הטבלאות
npm run seed                # נתוני הדגמה (רק למסד מקומי, ראי הערה למטה)
npm run dev                 # השרת עולה על http://localhost:3000
```

- Swagger: <http://localhost:3000/api-docs>
- בדיקת בריאות: <http://localhost:3000/api/health>

**חשבונות הדגמה** (נוצרים על ידי `npm run seed`, לשימוש מקומי בלבד):

| תפקיד | אימייל | סיסמה |
|---|---|---|
| מנהל ראשי | `admin@example.com` | `Admin12345!` |
| מנהל גמ"ח | `manager1@example.com` | `Manager12345!` |
| לקוח | `customer@example.com` | `Customer12345!` |

> ה-Seed **מוחק את כל הנתונים** לפני שהוא מכניס נתוני הדגמה. לכן הוא מסרב לרוץ מול מסד נתונים מרוחק (בענן) ובסביבת `production`. זו הגנה מכוונת.

## משתני סביבה

הרשימה המלאה עם הסברים נמצאת ב-[`.env.example`](.env.example).

| משתנה | חובה? | הסבר |
|---|---|---|
| `DATABASE_URL` | כן | כתובת החיבור ל-PostgreSQL |
| `JWT_SECRET` | כן | מפתח סודי, 32 תווים לפחות |
| `JWT_EXPIRES_IN` | לא | תוקף ה-Token (ברירת מחדל `8h`) |
| `CORS_ORIGIN` | מומלץ | כתובות ה-React המורשות, מופרדות בפסיק |
| `PORT` | לא | ברירת מחדל 3000 (בענן מוגדר אוטומטית) |
| `SEED_ADMIN_EMAIL`, `SEED_ADMIN_PASSWORD` | לא | אם מוגדרים, נוצר מנהל ראשי בעליית השרת (סיסמה 10 תווים לפחות) |

## בדיקות אוטומטיות

הבדיקות רצות מול **מסד נתונים נפרד** ומוחקות בו את כל הנתונים בין בדיקה לבדיקה. לכן:

1. צרי מסד נפרד, ושמו **חייב להכיל את המילה `test`** (למשל `gemach_test`). יש הגנה: אחרת הבדיקות מסרבות לרוץ.
2. הגדירי את הכתובת שלו במשתנה הסביבה `TEST_DATABASE_URL` (חובה, אין ברירת מחדל), והריצי:

   ```bash
   # Mac / Linux
   TEST_DATABASE_URL="postgresql://USER:PASSWORD@localhost:5432/gemach_test" npm test
   ```
   ```powershell
   # Windows PowerShell
   $env:TEST_DATABASE_URL="postgresql://USER:PASSWORD@localhost:5432/gemach_test"; npm test
   ```

3. המיגרציות מוחלות על מסד הבדיקות אוטומטית.

**לעולם אל תפני את `TEST_DATABASE_URL` למסד הנתונים האמיתי שלך.**

הבדיקות מכסות: הרשמה והתחברות, Token חסר/שגוי/פג תוקף, הרשאות לפי תפקיד ובעלות על גמ"ח, CRUD, ולידציה, חיפוש/סינון/מיון, מניעת גישה להשאלות פרטיות, אילוצי מסד הנתונים, תקינות Swagger והתאמתו לכל ה-Endpoints, CORS, ויצירת מנהל ראשי ממשתני סביבה.

```

  controllers/   קריאת הבקשה והחזרת תשובה

```

## אבטחה: מה מומש

- סיסמאות נשמרות כ-Hash (bcrypt, 12 מחזורים). לעולם לא מוחזרות בתשובות.
- Token עם תוקף מוגבל. הסוד ב-`JWT_SECRET` (משתנה סביבה). אלגוריתם HS256 בלבד (נדחה גם Token ללא חתימה).
- הזיהוי והתפקיד נקבעים בשרת מה-Token ומהמסד, בכל קריאה. אי אפשר "להצהיר" על משתמש או תפקיד אחר.
- בדיקות הרשאה ובעלות בצד השרת: מנהל גמ"ח אחד לא רואה ולא משנה גמ"ח אחר.
- הודעת התחברות זהה לאימייל שגוי ולסיסמה שגויה. הגבלת קצב לניסיונות התחברות והרשמה.
- הגנות מסד נתונים ברמת ה-DB: אילוצי כמויות ותאריכים, וייחודיות לבקשה ממתינה.
- `helmet`, CORS ניתן להגדרה, הגבלת גודל גוף בקשה, ושגיאות פנימיות לא נחשפות ללקוח.

### ידוע ומתועד

- `npm audit` מדווח על אזהרה בדרגת "גבוהה" בחבילת עזר (`deepmerge-ts`) שבתוך כלי שורת הפקודה של Prisma 6. היא רצה בזמן בנייה והפעלה ולא מעבדת קלט של משתמשים. התיקון המוצע על ידי npm הוא שדרוג ל-Prisma 7 (שינוי שובר), ולכן הוא לא בוצע. כדאי לבדוק מדי פעם אם יצאה גרסה 6 מתוקנת.
- אין התנתקות מצד השרת (Logout): Token תקף עד שפג תוקפו. ההתנתקות נעשית במחיקת ה-Token בצד הלקוח.
- ההשאלות שהוחזרו נמחקות ולא נשמרת היסטוריה (כפי שנקבע באפיון).
- חיפוש חפץ פועל לפי הטקסט שנכתב בשם החפץ ("מיקסר" לא ימצא "מערבל").
